# Архитектура и алгоритм

Правила задачи с кодами `R-...`: [rules.md](rules.md). Ниже - как каждое правило реализовано.

## Конвейер

```
GeoJSON (до 3 ГБ)
  → 1. загрузка: потоковый разбор, проверка, EPSG:4326 → EPSG:32637, PostGIS            ingest/, dataset/
  → 2. сценарий: объекты сети и ОКС + ограничения в районе расчёта (bbox + буфер)       solve/SolutionRepository
  → 3. контекст: топология существующей сети, «своё» здание каждой ОКС, слои по ДУ     route/Context, ExistingNetwork
  → 4. маршрут: граф видимости + A* с ограничением угла                                 route/ObstacleLayer, Router
  → 5. дерево: звезда, жадная вставка с полной ценой ΔS, локальный поиск               tree/Solver, TreeTargets
  → 6. ДУ и предельная длина, перепроверка геометрии с новыми отступами                 tree/Sizer, Solver.sizeAndValidate
  → 7. спрямление, стоимость и S, разбиение на участки base/special                     tree/Solver.straighten, Evaluator
  → 8. до 3 вариантов, независимая проверка правил, выгрузка GeoJSON                    tree/Validator, solve/GeoJsonExporter
  → 9. режим с глубиной: профиль по каждому ребру, K_гл, свои варианты и файл           tree/DepthProfiler
```

Все числа (таблицы 1 и 2, стоимости, веса S, допуски) - в `application.yml`, префикс `heat`. В коде нет
координат, id и параметров конкурсного датасета.

## 1. Загрузка

- `GeoJsonStreamReader` читает `FeatureCollection` через Jackson `JsonParser`: в памяти один Feature,
  поэтому размер файла на RAM не влияет. Файл сначала ложится на временный диск (volume `uploads`).
- `IngestProcessor` проверяет обязательные атрибуты и тип геометрии по сущности, перепроецирует
  в EPSG:32637 (proj4j), исправляет невалидные геометрии (`GeometryFixer`), собирает отчёт диагностики.
- Объекты пакетами пишутся в PostGIS (`feature`, GiST-индекс). id хранится строкой с признаком «был числом»,
  на выходе тип восстанавливается.
- Для расчёта ограничения читаются только в районе объектов сети и ОКС (`ST_Expand(ST_Extent(...))`).

## 2. Подготовка (route/Context, ExistingNetwork)

- **Область поиска (R-GEO-06):** bbox ОКС, сети, камер и источника + `heat.geometry.search-area-buffer-m`.
- **Топология сети (R-IN-05):** отрезки линий в STR-дереве; для каждой существующей камеры считаются занятые
  примыкания: конец линии в камере = 1, линия насквозь = 2 (R-TOP-05). Несвязность сети - в диагностику.
- **Своё здание ОКС (R-IN-02):** ближайший полигон `oks`, содержащий точку или ближе
  `oks-polygon-tolerance-m`. Точка вне полигона, но в зоне его отступа тоже считается «своей»
  (иначе недостижима), с записью в диагностику.

## 3. Пространство допустимых положений трубы (route/ObstacleLayer)

Трубу считаем линией нулевой ширины, отступы переносим на препятствия. Для каждого ДУ свой слой (лениво, с кэшем):

| Ограничение | Модель |
|---|---|
| запрет (`oks`, `park`, `water`, `railway`…) | контур упрощается на δ, расширяется на `d_min(ДУ) + w/2 + δ + запас` (mitre-буфер: угол не ближе отступа) и становится непроходимым (R-OKS-01, R-RST-01/02) |
| `road`, `tram_tracks` (полигон) | «мягкая» зона: полигон + отступ. Внутрь можно только прямым отрезком насквозь, угол к контуру ≥ 45°, отрезок продолжается прямо ≥ 3 м за обе границы (спецучасток = полигон + 3 м, R-RST-05/06/07) |
| `gas_pipeline`, `power_cable`, существующая `heat_network` (линии) | коридор `d_min + w/2 + w_огр/2` (R-RST-03), пересекается прямым отрезком, спецучасток ±2 м от точки пересечения |
| неизвестный `restriction_type` | запрет с отступом `unknown-restriction.offset` (допущение 5) |

Пересечение нескольких спецзон на одном отрезке: части с разным набором ограничений, в стоимость `max(K)` (R-RST-08).

**Узлы графа видимости:** выпуклые вершины расширенных препятствий (кратчайший путь огибает только их),
вершины мягких зон, точки вдоль дорог и коридоров с шагом `road-sample-step-m` (чтобы повернуть сразу
после перехода) и редкая сетка на открытых местах. Рёбра строятся лениво, только касательные (ребро не уходит
внутрь препятствия в своей вершине), в радиусе `visibility-radius-m`.

## 4. Маршрут (route/Router)

- **A* по состояниям «(предыдущая вершина, вершина)»:** переход с углом отклонения больше
  `max-turn-angle-deg` (90°) запрещён (R-GEO-02). Трасса - прямые отрезки с поворотами в вершинах (R-GEO-01).
- **Цена ребра = вклад в S:** `L · (0,7 · c(ДУ) · K / 25 000 000 + 0,003)`, спецучастки с K_спец.
  Небольшой штраф за поворот (`turn-penalty-m`) выбирает из равных путей тот, где меньше изломов (R-GEO-03);
  в стоимость он не входит.
- **Эвристика:** расстояние до ближайшей цели × минимальная цена метра + минимальная цена узла (допустима).
- **Старт от ОКС (R-OKS-02):** финальный прямой отрезок от точки через ближайшую точку границы своего здания
  до выхода из его зоны отступа; на нём отступ до своего здания не проверяется, остальные - да.
  Если из ближайшей точки маршрута нет (выход во двор, закрытый отступами соседей), пробуются следующие
  точки границы по возрастанию расстояния (допущение 4, пишется в заметки варианта).
- **Цели - врезка (R-TIE):** основание перпендикуляра на ближайших отрезках сети и их концы. Если в 10 м есть
  камера со свободным примыканием, врезка идёт в неё (R-TIE-02, 5 млн за участок, R-CH-03), иначе новая камера
  по max ДУ примыканий, включая ДУ линии (R-TIE-03, R-CH-01). На последнем отрезке коридор линии врезки
  не проверяется.
- **Цели - новая сеть:** ветвление на ребре (новая камера) или в камере со свободным примыканием.
  Цена цели - полное приращение S: камера + удорожание всех вышележащих участков, у которых растёт расход
  и, возможно, ДУ.
- **Запрет пересечений (R-TOP-06):** трасса не пересекает и не касается уже построенных участков,
  кроме точки присоединения.

## 5. Дерево (tree/Solver)

Задача - дерево Штейнера с ценой узлов и нелинейной ценой рёбер (NP-трудная), поэтому эвристики:

1. **Звезда:** каждая ОКС отдельно к существующей сети - всегда допустимая базовая линия.
2. **Жадная вставка** с разным порядком ОКС (ближние первыми, крупный расход первым, дальние первыми,
   случайные): каждая ОКС подключается к лучшей цели из п. 4 по полному ΔS. Лес вместо дерева получается
   сам, когда отдельная врезка дешевле (R-TOP-02, R-TIE-05).
3. **Локальный поиск:** вынуть ОКС (с ненужной больше веткой; камера без ветвления склеивается в одно ребро)
   и вставить заново; принять, если S уменьшился. Повторять до бюджета времени `solver.time-budget-s`.
4. **Другая врезка:** повтор с запретом точек врезки лучшего решения - содержательно другой вариант.

Ограничения камер: ветвление только в камере (R-TOP-04), не больше 4 примыканий, 1 вверх (R-TOP-05);
у новой камеры-врезки линия насквозь занимает 2.

## 6. ДУ и предельная длина (tree/Sizer)

- Расход участка = сумма `flow_tph` ОКС в поддереве (R-FLOW-01), меняется только в камерах.
- ДУ = минимальный по `Q_max`, но не меньше ДУ дочерних участков (монотонность к врезке, R-DN-04).
- Для каждого пути ОКС → врезка непрерывные фрагменты одного ДУ проверяются на `L_max` (R-LEN).
  При превышении пробуется поднять ДУ каждого ребра фрагмента или всего фрагмента; берётся вариант,
  который уменьшает превышение с наименьшим ростом стоимости. Повтор до устранения.
- ДУ вырос → отступы больше → каждое ребро перепроверяется на слое нового ДУ и при нарушении
  перестраивается между своими узлами. Камеры ветвления сразу ставятся там, где они допустимы и при
  максимальном ДУ сети.

## 7. Отделка, стоимость, выход

- **Спрямление (R-GEO-03):** вершина удаляется, если прямой отрезок без неё допустим и углы соседей ≤ 90°;
  почти коллинеарные вершины (< 1°) склеиваются.
- **Стоимость (раздел 6 rules.md):** участки `L · c(ДУ) · K`, новые камеры по таблице, врезки в существующие
  камеры, штраф за неподключённые, `S = 0,7 · C / 25 млн + 0,3 · L / 100`.
- **Выход (раздел 7):** участки режутся на границах спецпроходов, там ставится `technical_node`; повороты -
  внутренние вершины. Дополнительные свойства: `special_restriction_types`, `k_spec`, `chamber_role`,
  в `variant_summary` - `strategy`, `unconnected_reasons`, `validation_errors`, `notes`.
- **Варианты (R-VAR):** пул решений всех стратегий сортируется по S; вариант берётся, если отличается от уже
  выбранных: `1 − площадь(коридоры A ∩ B) / площадь(A ∪ B) ≥ variants.min-difference` при коридоре 5 м.

## 7а. Бюджет времени и улучшение (tree/Solver.solve)

- До 50% бюджета `solver.time-budget-s`: жадная вставка + локальный поиск для стратегий по очереди,
  случайные перезапуски - пока есть время.
- До 65%: вариант с другой врезкой. «Звезда» считается только до 40 ОКС (на больших наборах бесполезна).
- Остаток: LNS-шлифовка лучшего решения - вынуть группу из 2-5 соседних ОКС и вставить заново
  в случайном порядке; выводит из локальных оптимумов одиночной перевставки.
- Если ребро после роста ДУ не перестраивается, ОКС его поддерева вставляются заново.

Замеры (Apple M-series в Docker, параллельно с другими проектами):

| Набор | ОКС | Время | S | Нарушений |
|---|---:|---:|---:|---:|
| конкурсный | 17 | 15-20 с | 13,3 | 0 |
| демо (конкурсный + 2 дороги + газопровод) | 17 | 15-20 с | 14,6 | 0 |
| синтетический квартал 40×40 зданий, дорога | 78 | 60 с | 80,3 | 0 |

## 8. Независимая проверка (tree/Validator)

Каждый вариант проверяется заново по **исходной** геометрии ограничений (не по буферам оптимизатора):
структура леса и число примыканий, углы, пересечения новых участков, отступы до ограничений и сети,
расходы, ДУ, монотонность, предельная длина. Список нарушений попадает в `validation_errors` и на карту.
На конкурсном датасете нарушений 0.

## 9. Неподключённые ОКС (R-UNC)

ОКС не подключается, только если маршрут не найден: нет выхода из здания ни через одну точку границы,
A* исчерпал граф, расход больше максимального ДУ. Причина пишется в `unconnected_reasons`, штраф - в S.
Отказаться от подключения ради лучшего S оптимизатор не может: неподключённая ОКС всегда хуже любого
подключения (штраф 100 млн).

## 10. Режим с глубиной (tree/DepthProfiler)

План трассы берётся из 2D-вариантов (правила разрешают тот же маршрут), по каждому ребру строится
продольный профиль глубины верха габарита:

1. Требования вдоль ребра - спецучастки с вертикальным правилом (таблица 2): дорога/трамвай - верх
   не мельче 1,0/1,2 м; газ, кабель, теплосеть - выше (`h + h_габ + просвет ≤ h_огр`) или ниже
   (`h ≥ h_огр + h_габ_огр + просвет`). Наложения - пересечение допустимых глубин.
2. Для каждого требования выбирается глубина с минимальным K_гл, ближайшая к обычной 3,0 м и достижимая
   от текущей с уклоном ≤ 0,1. Спуск/подъём → постоянная глубина → возврат к 3,0 м, если до следующего
   препятствия хватает места на два перехода; иначе трасса остаётся на изменённой глубине.
3. Недостижимое требование помечается «требует ручной проработки» в `validation_errors`.
4. Участки режутся на изломах профиля и в точке h = 3,0 м (там меняется K_гл, ставится technical_node);
   `K_гл` участка - среднее по концам, стоимость `L · c · K_спец · K_гл`.
5. Варианты режима ранжируются отдельно и выгружаются отдельным файлом (`?mode=depth`, R-VAR-04).

Допущение 6: глубины участков, сходящихся в камере, не обязаны совпадать (камера - условная точка).

## Допущения до ответа организаторов

1. Угол ≤ 90° ограничивает только повороты трассы; в камере и точке врезки угол не ограничен.
2. Минимального расстояния между новыми участками нет; запрещены пересечения и касания вне узлов.
3. Коридор газа/кабеля/теплосети пересекается прямым отрезком насквозь; спеццена на ±2 м, остаток коридора -
   по обычной цене.
4. Если выход из ближайшей точки границы своего здания перекрыт, берётся следующая допустимая точка.
5. Неизвестный `restriction_type` - запрет с отступом 1 м и предупреждение в диагностике.

## Границы применимости

- Режим с глубиной не меняет план трассы относительно 2D: если под препятствием нужно заглубление,
  оно строится профилем, а не обходом в плане.
- Граф видимости ограничен радиусом `visibility-radius-m`: длинные пути строятся через промежуточные узлы
  и потом спрямляются; для очень больших территорий нужен бюджет времени больше 60 с.
- Жадная вставка и локальный поиск не гарантируют глобальный оптимум дерева Штейнера; качество
  повышается числом перезапусков `solver.greedy-restarts` и бюджетом `solver.time-budget-s`.
- Дорога, заданная линией, а не полигоном, обрабатывается как линейная коммуникация с углом ≥ 45°
  (вопрос 5 к организаторам).
