# Архитектура и алгоритм

Правила задачи с кодами `R-...`: [rules.md](rules.md).

## Конвейер

```
GeoJSON (до 3 ГБ)
  → 1. загрузка: потоковый разбор, проверка, EPSG:4326 → EPSG:32637, PostGIS        [готово]
  → 2. топология существующей сети: snap концов линий и камер                       [план]
  → 3. пространство поиска: bbox + буфер, расширенные препятствия по классам ДУ     [план]
  → 4. маршрут ОКС → сеть: граф видимости + A*                                      [план]
  → 5. дерево: объединение ОКС, камеры ветвления, врезки                             [план]
  → 6. ДУ и предельная длина: снизу вверх до неподвижной точки                       [план]
  → 7. постобработка: спрямление, пересечения, технические узлы                      [план]
  → 8. стоимость, S, до 3 вариантов, выгрузка GeoJSON в WGS 84                       [план]
```

## 1. Загрузка (готово)

- `GeoJsonStreamReader` читает `FeatureCollection` через Jackson `JsonParser`: в памяти один Feature,
  поэтому размер файла на RAM не влияет.
- `IngestProcessor` проверяет обязательные атрибуты и тип геометрии по сущности, перепроецирует
  в EPSG:32637 (`Projection`, proj4j), исправляет невалидные геометрии (`GeometryFixer`), собирает
  отчёт диагностики `IngestReport`.
- Принятые объекты пакетами по `heat.ingest.batch-size` пишутся в таблицу `feature`
  (геометрия в WKB, GiST-индекс). id хранится строкой вместе с признаком «был числом»,
  чтобы на выходе вернуть исходный тип.
- HTTP-запрос сразу возвращает `id`, разбор идёт в пуле `ingest-*`. Загрузки, прерванные
  перезапуском, при старте помечаются `FAILED`.

## 2-8. План алгоритма

**Препятствия.** Отступ зависит от ДУ (`d_min + w(ДУ)/2`, R-RST-02), поэтому слои расширенных
препятствий строятся по классам ДУ. Запреты непроходимы. `road`/`tram_tracks` проходятся только
рёбрами-спецпереходами: один прямой отрезок, угол ≥ 45°, длина = ширина + 2×3 м, цена × K_спец.
Коридоры `gas_pipeline`/`power_cable`/чужой теплосети пересекаются прямым отрезком ±2 м.

**Маршрут.** Граф видимости (касательные рёбра) между вершинами расширенных препятствий в коридоре
поиска, пространственный индекс `STRtree`. A* по состояниям (вершина, входящее ребро), чтобы
запретить повороты > 90° (R-GEO-02). Вес ребра - вклад в `S`:
`0,7 · c(ДУ) · K / 25 000 000 + 0,003` за метр. Цели: существующие камеры и проекции вершин графа
на линии `heat_network` (кандидаты врезки, R-TIE).

**Дерево.** Задача Штейнера с ценой камер (NP-трудная): стартовое решение «звездой» и жадным
Takahashi-Matsuyama, затем локальный поиск (перевес поддеревьев, сдвиг точки ветвления, разбиение
на части с разными врезками). Степень камеры ≤ 4 (R-TOP-05).

**ДУ.** Расход снизу вверх по дереву, минимальный ДУ по `Q_max`, монотонность к врезке,
проверка `L_max` по каждому пути, повышение ДУ до неподвижной точки (R-DN, R-LEN). Если ДУ вырос,
трасса перепроверяется на слое препятствий с бо́льшим отступом.

**Варианты.** Разные эвристики дерева, разные врезки, penalty method. Отличие вариантов оценивается
по расстоянию Хаусдорфа или доле общей длины (R-VAR-02).
