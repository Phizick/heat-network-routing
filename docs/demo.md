# Сценарий демонстрации

Соответствует пункту «Что покажем на демо» из ТЗ (раздел 13 [rules.md](rules.md)).
Всё показывается на карте `http://localhost:8090/`, при необходимости - через Swagger `/swagger-ui.html`.

## 0. Подготовка

```bash
docker compose -p heat-routing up -d --build
```

Открыть http://localhost:8090/. Слева панель, справа карта.

## 1. Загрузка без ручной подготовки

- «Выбрать GeoJSON» → конкурсный датасет → «Загрузить».
- Панель показывает: принято 144, отброшено 0, счётчики по типам, суммарный расход 488,72 т/ч.
  Если бы в данных были проблемы, они появились бы строкой «Замечания» (коды в [api.md](api.md)).
- На карте сразу видны здания и ограничения, существующая сеть (красная, толщина по ДУ), камеры,
  источник и точки ОКС (размер кружка - расход).

Что сказать: файл читается потоком, в память целиком не грузится; 331 МБ (140 тыс. объектов) принимаются
за 32 с, приложение при этом держит 533 МБ. Ограничения хранятся в PostGIS с пространственным индексом,
в расчёт берутся только объекты в районе сети и ОКС.

## 2. Запуск расчёта

- Кнопка «Построить сеть». Расчёт идёт в фоне, статус обновляется сам.
- Конкурсный датасет: около 45 с, 3 варианта.
- Для показа «быстро» и «подольше»: `POST /api/datasets/{id}/solve?budgetSeconds=15` и `?budgetSeconds=120`.

## 3. Сеть, врезки, расходы, ДУ, предельная длина

- Таблица вариантов: S, стоимость, длина, число камер и врезок, колонка «Правила».
- Клик по участку на карте - всплывающее окно: ДУ, расход, длина, стоимость, способ прокладки,
  идентификаторы начального и конечного узлов.
- Цвет линии - ДУ (легенда внизу панели): магистраль от кластера ОКС толще и темнее, ответвления тоньше.
- Клик по камере: роль (врезка или ветвление), диаметр (максимальный ДУ примыканий, включая существующую
  линию), стоимость.

Что сказать: расход участка - сумма ОКС ниже по течению; ДУ минимальный по пропускной способности,
не убывает к врезке; предельная длина проверяется по каждому пути ОКС → врезка, при нарушении ДУ поднимается.

## 4. Работа с ограничениями

- Кнопка «Демо-набор с дорогами и газопроводом» (конкурсный датасет плюс две дороги и газопровод,
  R-IN-03 разрешает дополнять копию входа) → «Построить сеть».
- На карте: трассы пересекают дороги строго поперёк, спецучастки показаны пунктиром, на их границах
  стоят технические узлы. Клик по спецучастку: `laying_method = special`, тип ограничения, K_спец.
- Показать, что вдоль дороги или в её зоне отступа трасса не идёт, обходит здания с отступом по ДУ.

## 5. Неподключённые ОКС

- Если маршрута нет, ОКС попадает в `unconnected_oks_ids`, под таблицей выводится причина
  (нет выхода из здания, маршрут не найден, расход больше максимального ДУ), в S входит штраф.
- На конкурсном и демо-наборе подключаются все 17 точек.

## 6. Сравнение вариантов и ранжирование

- Строки таблицы переключают вариант на карте, «показать все варианты» рисует их вместе (невыбранные серым).
- Ранг 1 - минимальный S. Под таблицей - разбивка: трубы, камеры, врезки, итоговая стоимость, длина.
- Варианты отличаются содержательно: другая врезка, другое объединение ОКС (метрика - доля общего коридора).

## 7. Режим с глубиной

- Переключатель «с глубиной»: свои варианты, своё ранжирование, отдельный файл.
- Клик по участку: `depth_start`, `depth_end`, `k_depth`. Под дорогой верх габарита не мельче 1,0 м,
  газопровод обходится сверху (например, 2,37 м при просвете 0,2 м и габарите ДУ125).

## 8. Объяснимость и самопроверка

- Колонка «Правила»: независимый валидатор перепроверяет готовый вариант по исходной геометрии
  ограничений, а не по расширенным зонам оптимизатора. На конкурсном и демо-наборе нарушений 0.
- Заметки варианта: где выход из здания взят не из ближайшей точки границы и почему.
- Диагностика данных загрузки: неизвестные типы ограничений, несвязность существующей сети, дубликаты id.

## 9. Выгрузка

- «Скачать GeoJSON»: формат раздела 7 ТЗ, все варианты в одном файле, `variant_id`, `variant_summary`
  с рангом, стоимостями, длиной, S и списком неподключённых.
- В режиме с глубиной скачивается второй файл со своими `depth_start`/`depth_end`.

## 10. Алгоритм и границы применимости

Кратко по [architecture.md](architecture.md): препятствия с отступом по ДУ → граф видимости и A*
с ограничением угла → жадная вставка с полной ценой ΔS, локальный поиск и LNS → ДУ и предельная длина →
проверка правил → варианты. Границы применимости и допущения - в конце того же файла.
